# Swagger UI в проекте PAGEVA

Индивидуальное задание: задокументировать книги, экземпляры, читателей и выдачи; через Swagger показать поиск книги, выдачу конкретного экземпляра и возврат; описать ошибки «экземпляр уже выдан», «неизвестный читатель» и «просроченный возврат».

---

## Запуск

1. Запустите PostgreSQL (база `flyway`, как в `application.yml`).
2. Запустите `App` из IntelliJ IDEA (или `mvn spring-boot:run` в папке `back`). В логе должно быть `Started App`.
3. cd F:\PAGEVA_FLYWAY\front
   npm install
   npm start
4. Откройте в браузере:
   - Swagger UI: http://localhost:8080/swagger-ui.html (перенаправит на `/swagger-ui/index.html`);
   - описание в JSON: http://localhost:8080/v3/api-docs;
   - описание в YAML: http://localhost:8080/v3/api-docs.yaml.

> **Чтобы данные совпадали с инструкцией**, начните с чистой базы: в pgAdmin или DBeaver выполните `DROP DATABASE flyway;` и `CREATE DATABASE flyway;`, затем перезапустите приложение. Flyway заново применит миграции V1–V7 с тестовыми данными. Если базу не пересоздавать, ИД ниже могут отличаться. Тогда берите их из ответов шагов 3–5.

---

## Сценарий демонстрации в Swagger

Чтобы выполнить запрос в Swagger: раскройте метод, нажмите **Try it out**, заполните параметры, нажмите **Execute**. Ответ появится ниже, в блоке **Server response**.

### Шаг 1. Обзор документации
Покажите главную страницу: заголовок «Library API» и разделы **Книги**, **Экземпляры**, **Читатели**, **Выдачи**, **Штрафы**. Остальные контроллеры проекта (подписки, скидки и т. д.) Swagger показывает автоматически под именами вида `subscription-controller`. Раскройте внизу блок **Schemas** и покажите `BookCopyDto` и `BookOrderingDto` с описаниями полей.

### Шаг 2. Авторизация под библиотекарем
1. Нажмите **Authorize**. В блоке `basicAuth` введите `manager` / `Library1!`, нажмите **Authorize**, затем **Close**.
2. Раздел «Читатели» → `POST /users/login` → **Try it out** → **Execute**.
3. Скопируйте значение `data.token` из ответа (без кавычек).
4. Снова нажмите **Authorize**. В блоке `bearerAuth` вставьте токен, нажмите **Authorize**, затем **Close**. После обновления страницы токен сбрасывается, тогда повторите шаг 2.

### Шаг 3. Поиск книги
`GET /books/search`, `query = Война`.
Ожидается: 200, книга «Война и мир», `id = 1`, `quantityFree = 1`. В массиве `copies` видны экземпляры книги.

### Шаг 4. Экземпляры книги
`GET /books/{bookId}/copies`, `bookId = 1`.
Ожидается: `INV-0001-001` в статусе `RESERVED`, `INV-0001-002` в статусе `ISSUED`, **`INV-0001-003` (id = 3) в статусе `AVAILABLE`**. Его и будем выдавать.

### Шаг 5. Поиск читателя
`GET /users/readers`, `query = Смирнова`.
Ожидается: читатель `id = 3`, «Смирнова Мария Андреевна».

### Шаг 6. Выдача конкретного экземпляра
`POST /books/orderings/issue`, `readerId = 3`, `copyId = 3`, `days = 14`.
Ожидается: 200, `message = "Success Issue"`, в `data`: `status = DONE`, `inventoryNumber = INV-0001-003`, `ownerFio = Смирнова Мария Андреевна`. **Запомните `data.id`** (на чистой базе это `10`).
Если повторить шаг 4, у `INV-0001-003` будет статус `ISSUED`.

### Шаг 7. Ошибка «экземпляр уже выдан»
Повторите шаг 6 с теми же параметрами.
Ожидается: **409**, `"Экземпляр INV-0001-003 уже выдан"`.

### Шаг 8. Ошибка «неизвестный читатель»
`POST /books/orderings/issue`, `readerId = 999`, `copyId = 3`.
Ожидается: **404**, `"Читатель не найден: 999"`.
Дополнительно можно показать `readerId = 2` (это библиотекарь, а не читатель): тоже 404.

### Шаг 9. Возврат вовремя
`PATCH /books/orderings/{id}/returned`, `id` из шага 6 (`10`).
Ожидается: 200, `message = "Success Returned"`, `status = RETURNED`, `overdueDays = 0`, штрафа нет. Экземпляр `INV-0001-003` снова `AVAILABLE`.
Повторите этот же запрос: **409**, `"Действие недоступно для заявки в статусе «Возвращено»"`.

### Шаг 10. Просроченный возврат
`PATCH /books/orderings/{id}/returned`, `id = 3`. Это выдача из V1: reader2, «Преступление и наказание», взята 2026-09-20 на 14 дней.
Ожидается: 200, `message = "Возврат просрочен на N дн. Начислен штраф X BYN"`, в `data`: `overdueDays = N`, `fineAmount = X`, `fineStatus = UNPAID`. N считается от 2026-10-04 до сегодняшнего дня: на 12.11.2026 это 39 дней и 581.10 BYN.

### Шаг 11. Последствие просрочки
`POST /books/orderings/issue`, `readerId = 4`, `copyId = 3`.
Ожидается: **409**, `"У читателя неоплаченный штраф за просроченный возврат"`.
По желанию: раздел «Штрафы» → `GET /fines`, найдите штраф reader2 (ownerId = 4) и оплатите его через `PATCH /fines/{id}/paid`. У reader2 два штрафа (один остался из V1), поэтому оплатить нужно оба. После этого шаг 11 даст 200.

### Шаг 12. Описание ошибок в документации
Раскройте, не выполняя запросы:
- `POST /books/orderings/issue`: в **Responses** коды 200, 403, 404 (примеры «Неизвестный читатель», «Нет экземпляра») и 409 (выпадающий список примеров: «Экземпляр уже выдан», «Неоплаченный штраф»);
- `PATCH /books/orderings/{id}/returned`: 200 с примерами «Возврат вовремя» и «Возврат с просрочкой», 409 «Повторный возврат», 404;
- `PATCH /books/copies/{id}/status`: 409 «Экземпляр в выдаче».
